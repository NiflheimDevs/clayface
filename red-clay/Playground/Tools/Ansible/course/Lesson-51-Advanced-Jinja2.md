# Lesson 51 — Advanced Jinja2

## Learning objectives

- Use filters, conditionals, and loops in templates responsibly.
- Keep data transformation readable.
- Distinguish template logic from Ansible task logic.

## Prerequisites

Lessons 10, 14, and 29.

## Concept

Jinja2 supports filters (`|`), conditional blocks, loops, and tests. It is useful for rendering repeated configuration syntax from well-structured variables, such as several upstream servers. Templates should remain primarily presentation: module selection, error handling, service actions, and host targeting belong in tasks/roles.

Use whitespace controls and defaults carefully; silently defaulting a required variable can produce a valid-looking but wrong configuration. Validate rendered service configuration before reload.

## Mental model

Jinja2 is the formatter for structured data, not the control plane for your deployment.

## Example

Given:

``` yaml
web_nginx_upstreams:
  - name: app01
    address: 10.10.20.11:8080
```

Template fragment:

``` jinja2
upstream application {
{% for server in web_nginx_upstreams %}
    server {{ server.address }};
{% endfor %}
}
```

`{% for %}` repeats literal configuration lines for each dictionary. `server.address` accesses that item's key. The variable data should be validated—an invalid address turns into an invalid service config, not a template problem.

## Practical exercise

Render a harmless list of lab hostnames from a variable list. Then add a conditional comment only when the list is empty. Keep all service start/reload decisions out of the template.

## Expected result

The output is readable configuration text matching the input list; an unchanged list yields an unchanged render.

## Common mistakes

- **Embedding credentials in loop output and then using diff.** Output handling still matters.
- **Putting business decisions in deeply nested templates.** Move them to variables/tasks.
- **Ignoring whitespace generated by control blocks.** Inspect rendered output.

## Key takeaways

Advanced Jinja2 turns structured variables into configuration syntax; clear data and validation remain more important than template cleverness.
